# Universal Roblox Tier List — Vercel + Supabase

Переписанная версия прикреплённого HTML-проекта. Интерфейс — React 19 + Vite; размещение — Vercel; база, регистрация, файлы, real-time сообщения и сигнализация звонков — Supabase. Исходный небезопасный JavaScript с локальными паролями и присвоением админских прав **не используется**.

## 1. Что входит в проект

- **Каталог:** 5 игр (DOORS: 2 отдельных раздела), 530 карточек, рейтинги, изображения, исходные описания (`196` записей ITEM_DATA) и отдельный справочник способностей (`252` записи).
- **Внешний вид:** 30 оригинальных цветовых тем, адаптивные страницы, карточки, профиль.
- **Аккаунты:** Supabase Auth, почтовая регистрация и подтверждение, восстановление пароля, ник, биография, аватар.
- **Данные:** избранное на всех устройствах, друзья и запросы, история личных сообщений.
- **Звонки:** 1:1 аудио/видео, демонстрация экрана во время видеозвонка, WebRTC с приватной сигнализацией Supabase Realtime. **ЗАПИСИ звонков и слежение за разговорами нет.**
- **Админка:** список пользователей, бан на сутки / разбан, назначение/снятие админа начальником. Проверки доступа и аудит операций находятся в PostgreSQL, а не в браузере.
- **Защита:** RLS, жёстко ограниченные SQL-права для колонок, owner-only Storage, проверка доступа к приватным каналам, контроль длины сообщений и SQL-ограничение частоты отправки.

## 2. Требования

- Node.js **22.12+** и npm.
- Аккаунт Supabase, новый проект Supabase.
- Аккаунт Vercel, GitHub (для самого удобного деплоя).
- HTTPS для микрофона, вебкамеры и screen sharing (Vercel предоставляет HTTPS).

## 3. Поднять Supabase

1. Создайте новый проект на https://supabase.com/dashboard . Дождитесь готовности Postgres.
2. Откройте **SQL Editor → New query**. Скопируйте весь файл `supabase/migrations/202610260001_initial.sql` и исполните его **один раз**. Не повторяйте на рабочей базе, не просмотрев изменения схемы.
3. Откройте **Authentication → Providers → Email**. Оставьте почтовую авторизацию; **включите подтверждение Email**. Для отправки писем в реальном проекте настройте **SMTP** (лимиты встроенной отправки подходят не для масштабного сайта).
4. Откройте **Authentication → URL Configuration**. В `Site URL` пропишите адрес будущего сайта, а в **Redirect URLs** добавьте `http://localhost:5173/**` (для разработки) и `https://ВАШ-ПРОЕКТ.vercel.app/**` (для сайта). Для своего домена добавьте и его.
5. Откройте **Realtime → Settings**, выключите **Allow public access**, чтобы работали только приватные каналы. SQL-миграция уже настраивает RLS на `realtime.messages`. Таблицы `messages` и `friendships` уже добавлены в `supabase_realtime` publication.
6. **Project Settings → API / Connect:** скопируйте `Project URL` и **Publishable key** (публичный `sb_publishable_...`; для старых проектов допустим публичный `anon`). **Secret key / service_role не вставляйте в VITE_ переменные!**
7. Откройте **Authentication → Security and Protection**: включите **CAPTCHA** при регистрации/входе, настройте лимиты почтовых запросов. Для текущего интерфейса нужна интеграция виджета CAPTCHA перед принудительным включением CAPTCHA, иначе регистрация может перестать работать. Аналогично включите MFA для аккаунта начальника на уровне Auth/UI, если планируете его требовать.

## 4. Запуск на Windows (PowerShell)

Выполните команды в каталоге с `package.json`:

```powershell
node -v
npm install
Copy-Item .env.example .env
notepad .env
npm run check
npm run dev
```

Измените `.env` до запуска:

```dotenv
VITE_SUPABASE_URL=https://abcdefg.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxxxxxxxxxxxxxxxxx
```

После `npm run dev` откройте http://localhost:5173 . Значения выше — только пример; используйте свои данные из Supabase. `.env` не загружайте в GitHub.

## 5. Деплой на Vercel

1. Создайте **приватный GitHub-репозиторий** из файлов проекта и отправьте туда исходники **без `.env`**.
2. Откройте https://vercel.com/new , импортируйте репозиторий.
3. Framework Preset: **Vite**. Root Directory: корень с `package.json`. Build Command: `npm run build`, Output Directory: `dist` (оба уже описаны в `vercel.json`).
4. Добавьте в **Project Settings → Environment Variables** два значения:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_PUBLISHABLE_KEY`
5. Сделайте Deploy. Проверьте регистрацию, email-подтверждение и вход. Обновите `Site URL`/`Redirect URLs` в Supabase на фактический адрес Vercel.
6. Для своего домена добавьте его через **Vercel → Domains** и в Supabase Redirect URLs.

> Настройки `vercel.json` задают CSP, запрет встраивания сайта, `nosniff` и другие HTTP-заголовки. При замене внешних сервисов медиа/связи корректируйте CSP осознанно, не устанавливайте `script-src 'unsafe-inline'`.

## 6. Как сделать себя начальником (boss)

1. Зарегистрируйтесь на развёрнутом сайте и подтвердите email.
2. В **Supabase → SQL Editor** выполните запрос, подставив **СВОЙ настоящий email**:

```sql
update public.profiles
set role = 'boss'
where id = (
  select id from auth.users where lower(email) = lower('you@example.com')
);
```

3. Перезайдите на сайт. Откроется кнопка «Админка».

**Важно:** роль `boss` назначается **только в SQL Editor под владельцем проекта**, не через браузер. Браузеру недоступны обновления колонок `role` и `banned_until`. SQL-функция может выдать только `admin`, но не `boss`.

## 7. Проверка функциональности (желательно двумя тестовыми аккаунтами)

1. Создайте двух пользователей. Подтвердите оба email. Убедитесь, что они не видят чужого избранного.
2. Найдите второй ник, отправьте запрос, примите его со второго аккаунта. Проверьте сообщения в двух окнах: доставка по Realtime, отсутствие доступа постороннего пользователя.
3. Проверьте аудио- и видеозвонок между двумя разными устройствами. Дайте доступ к микрофону и камере. Экран доступен во время видеозвонка.
4. Загрузите аватар PNG/JPG/WebP до 2 МБ. Проверьте отклонение неподдерживаемого формата.
5. Попробуйте изменить `role` и `banned_until` прямым запросом в PostgREST с публичным ключом: доступ должен быть отклонён.
6. Попробуйте отправить сообщение от одного пользователя в чужую `friendship_id`, убедитесь в запрете RLS.
7. Назначьте начальника через SQL, проверьте бан/разбан, невозможность банить начальника и журнал `public.admin_audit` через SQL Editor.
8. Проверьте `npm run check`, `npm run build`, браузерную консоль и Lighthouse, затем проведите полноценный pentest перед публичным запуском.

## 8. Ограничения и особенности

- **Нельзя перенести пароли и сессии** из старого HTML: там они небезопасно хранились в localStorage. Пользователи должны создать аккаунты Supabase с новыми паролями; *не переносите старые пароли в БД*.
- Избранное ранее сохранялось локально, а теперь привязано к Supabase Auth. Автоматический импорт старого localStorage не предусмотрен.
- Чат нового сайта — личный, 1:1, для принятых друзей. Старый демонстрационный/локальный общий чат не сохранён как рабочий общий канал. Если понадобится публичный модерируемый чат, потребуется отдельная таблица, политики модерации и спам-защита.
- WebRTC использует публичный STUN, **без TURN-сервера**. На некоторых мобильных сетях или строгом NAT звонок не установится. Для надёжных звонков подключайте защищённый TURN-сервер с временными серверными учётными данными (отдельное доверенное API), никогда не встраивайте постоянные TURN-секреты в браузер.
- Перехват или аудиозапись чужих звонков не реализованы. Старая «админка» с фиктивными сообщениями и локальной сменой чужих паролей заменена безопасной моделью. Админка не просматривает личные переписки.
- Изображения исходного каталога хранят внешние URL Roblox/Wikia. Если внешний сайт удалит файл или запретит hotlink, картинка пропадёт; для постоянного хранения переместите изображения, на которые есть права, в свой Storage.
- Запрет пользователя проверяется при операциях SQL. Активные realtime-соединения могут сохранять уже выданные разрешения до обновления JWT/переподключения; при высоких требованиях к немедленному отзыву нужна дополнительная принудительная ротация токенов / завершение сеансов.
- Этот архив **не развёрнут на ваших аккаунтах Vercel/Supabase**. Результаты npm/build, интеграционный аудит и тест на нагрузку надо выполнить в вашем окружении.

## 9. Структура файлов

```text
RobloxTier_Vercel_Supabase/
├─ index.html                        # HTML entry (без inline JS)
├─ package.json                      # зависимости и команды
├─ vercel.json                       # Vercel + security headers
├─ .env.example                      # шаблон публичных переменных
├─ .gitignore
├─ README_RU.md                      # эта инструкция
├─ SECURITY_RU.md                    # модель угроз и проверки
├─ src/
│  ├─ main.jsx                       # React: каталог, UI, Auth, чат, админка, WebRTC
│  ├─ supabase.js                     # публичный Supabase-клиент
│  ├─ catalog.json                    # 530 карточек и ITEM_DATA
│  ├─ abilities.json                  # исходные гайды по навыкам
│  ├─ legacy.css                      # оригинальная цветовая палитра и UI-стили
│  └─ modern.css                      # адаптация для React
├─ supabase/migrations/
│  └─ 202610260001_initial.sql        # схемы, RLS, роли, Storage, realtime
└─ scripts/
   └─ security-check.mjs             # базовая статическая проверка
```
